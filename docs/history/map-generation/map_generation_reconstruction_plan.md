### 1.2 アルゴリズムの流れと目的・意味

#### 1.2.1 初期化フェーズ (initializeMap)
**アルゴリズム**: 2次元配列の初期化
**目的**: ゲームワールドの基盤となるグリッド構造の作成
**意味**: すべてのタイルを「空」の状態で初期化し、生成の基盤を整える

#### 1.2.2 空間分割フェーズ (splitSpace)
**アルゴリズム**: Binary Space Partitioning (BSP)
```typescript
// 再帰的空間分割
if (width < maxRoomSize * 2 + minRoomDistance ||
    height < maxRoomSize * 2 + minRoomDistance ||
    depth > 10) {
  createRoom(x, y, width, height);
  return;
}
```
**目的**: 効率的な部屋配置による空間の有効活用
**意味**: 領域を再帰的に分割し、自然な部屋構造を生成

#### 1.2.3 部屋生成フェーズ (createRoom)
**アルゴリズム**: サイズ制約付きの矩形生成
```typescript
// 部屋サイズの決定と配置
const roomWidth = Math.max(minRoomSize, Math.min(width - minRoomDistance * 2, maxRoomSize));
const roomHeight = Math.max(minRoomSize, Math.min(height - minRoomDistance * 2, maxRoomSize));
```
**目的**: プレイアブルな部屋空間の確保
**意味**: 各領域に適切なサイズの部屋を作成し、探索の基盤となる

#### 1.2.4 通路接続フェーズ (connectRooms)
**アルゴリズム**: L字型経路生成 + ランダム追加接続
```typescript
// X座標ソート順接続 + ランダム接続
for (let i = 0; i < sortedRooms.length - 1; i++) {
  createCorridor(roomA.x + Math.floor(roomA.width / 2),
                 roomA.y + Math.floor(roomA.height / 2),
                 roomB.x + Math.floor(roomB.width / 2),
                 roomB.y + Math.floor(roomB.height / 2));
}
```
**目的**: 部屋間の到達可能性の確保
**意味**: すべての部屋が接続され、探索可能なダンジョン構造を形成

#### 1.2.5 特徴追加フェーズ (addRandomFeatures)
**アルゴリズム**: 確率分布による地形要素配置
```typescript
// 地形要素の配置
this.stageData[y][x] = Math.random() < 0.7 ? TileType.WATER : TileType.MOUNTAIN;
// 特殊要素の配置
this.stageData[py][px] = TileType.PORTAL;
this.stageData[hy][hx] = TileType.HEAL;
```
**目的**: ゲームメカニクスの多様化
**意味**: 戦略的要素と回復機会を提供し、ゲーム体験を豊かにする

## 2. 現在のシステムの限界と課題

### 2.1 アルゴリズム設計の限界

#### 2.1.1 BSPアルゴリズムの構造的制約
```
┌─────────┐  ┌─────────┐
│  Room1  │  │  Room2  │
├─────────┤  ├─────────┤
│  Room3  │  │  Room4  │
└─────────┘  └─────────┘
```
**問題**: 矩形ベースの単調な部屋形状
**影響**: 視覚的なバリエーション不足

#### 2.1.2 通路生成の非効率性
```typescript
// ランダムなL字型通路
while (x !== x2 || y !== y2) {
  if (Math.random() < 0.5) {
    // 水平移動
  } else {
    // 垂直移動
  }
}
```
**問題**: 無駄な移動が発生する可能性
**影響**: 通路の複雑化とプレイヤーの迷路化

### 2.2 システムアーキテクチャの課題

#### 2.2.1 硬直化したパラメータ設定
```typescript
this.minRoomDistance = 3; // 固定値
const featureCount = Math.floor(this.width * this.height * 0.01); // 固定比率
```
**問題**: ゲームバランスの調整が困難
**影響**: 異なるフロアや難易度への対応不足

#### 2.2.2 アルゴリズムの単調性
```
┌─────────────────────┐
│ フロア1: 基本BSP    │
│ フロア2: 基本BSP    │
│ フロア3: 基本BSP    │
└─────────────────────┘
```
**問題**: フロアごとのバリエーション不足
**影響**: プレイヤーの探索意欲低下
