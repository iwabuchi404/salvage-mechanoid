# テスト整備ロードマップ

最終更新: 2026-08-11

## 目的

この文書は、今後のリファクタリングと機能拡張を安全に進めるために、追加すべきテストを優先度順に管理するチェックリストです。

カバレッジ率だけを目標にせず、変更対象ごとに次の観点を揃えます。

- 正常系
- 境界値
- 失敗時
- 破棄・再初期化後
- 関連システムへ送るイベントとデータ

2026-08-11 の修正後作業ツリーでは、次の検証が成功しています。

- TypeScript 型検査
- 本番ビルド

## 完了条件

各対象は、次の条件を満たした時点で「リファクタリング可能」と判断します。

- 公開 API と主要イベント payload がテストで固定されている
- 正常系だけでなく、入力不正、依存不在、破棄後の挙動が確認されている
- テストが実装コードを直接通っており、同じロジックをテスト側へコピーしていない
- 乱数、時間、描画依存を制御して再現可能である
- 対象モジュールのユニットテストと主要 E2E が両方成功する
- 本番ビルドと TypeScript 型検査が成功する
